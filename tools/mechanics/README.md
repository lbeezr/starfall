## Parked: supernova candidates

These are isolated rule experiments, not app features or adopted power-ups. No new runtime flag, save field, asset or dependency is added. The runner copies the current core into a temporary folder and applies a strict patch there; mismatched patches fail rather than silently using different rules.

Run `python3 tools/mechanics/run-supernova.py` for matching-identity recoloring, or add `--rotate` for cyclic identity rotation. Both execute fixture regressions and 200-seed samples before emitting JSON. The candidate threshold is five starlight; ordinary clears retain the three-starlight threshold. Recolor only orthogonal surviving colored neighbors of the original group before settling. Preserve survivor IDs and growth, ordinary Dusk removal, score conservation, preview and RNG. Never cascade. Rotation follows the existing `Jewel.allCases` order and is a diagnostic rule, not an approved character transformation order.

Policies clear every available group, choosing the first canonical group. They compare ordinary tap, charge whenever eligible, and charge only when it creates more immediately available groups. This last policy examines committed hypothetical states; it does not simulate a person's comprehension, finger timing, preview or charge gesture. Counts across policies have different visited states and denominators. `differingFollowups` compares settled boards; better/worse counts compare legal-group counts, not eventual survival or enjoyment. Equal group counts can conceal strategically different boards. Each committed state is checked for valid-save invariants; every clear is round-tripped and its next shower compared after restore.

The depth metrics also compare total immediately clearable starlight and overflow through the already announced shower with no intervening clear. `tapExamples` retains up to three exact pre-input states from the ordinary-tap trajectory where tapping preserves more clearable value or avoids immediate overflow. These are replay fixtures, not normal app saves. Future unseen previews may differ between branches. Zero observed overflow differences is not a proof of equivalence or lack of strategic depth.

Decision point: do not promote either version yet. The October 17 sample shows stronger immediate follow-ups overwhelmingly favor charging; neither establishes a sufficient reason to prefer a tap on eligible groups. Resolve the tradeoff and preview/comprehension design before adoption. The interaction lab below is parked following the user's shower-variety choice. Do not infer that a higher bot score means greater enjoyment. Archive/remove the lab when that mechanic is selected or abandoned; resume it only after the active shower comparison or a new user priority.

## Isolated native interaction lab

`python3 tools/mechanics/prepare-native-lab.py` prints a newly exported app folder, pinned to `30af812`. Open its `Starfall.xcodeproj` and run the shared Starfall scheme on a simulator. Use `--starfalls-reset --supernova-fixture` for the retained seed-124/shower-9 counterexample, or omit the fixture argument to play ordinary skies with the candidate interaction. Normal tap stays available. Groups worth five or more support a 0.65-second hold followed by release; dragging outside the original cell after arming cancels permanently for that touch. A shower, restart, pause, settings/background suspension, balance/motion change or scene settlement cancels the intent. Each touch carries a ticket so older callbacks cannot operate on a newer finger's intent.

The installed app is named **Supernova Lab**, bundle `com.starfall.supernovalab`, with defaults suite `starfall.supernova.lab`. It uses the matching-identity candidate only and appends focused hosted/UI checks to existing target-member files in the export. No production source, target membership or normal save is changed. This is deliberately a separate prototype rather than another permanent runtime flag. `MECHANICS-LAB.json` records the pinned commit and source-tool hashes (earlier exports used `SUPERNOVA-LAB.json`). On the local Xcode 27.1/arm64 simulator setup, use `ARCHS=arm64 ONLY_ACTIVE_ARCH=YES CODE_SIGNING_ALLOWED=NO` for builds/tests; unrestricted app/package simulator architectures did not agree.

The native supernova export uses its archived core patch from the pin. The offline supernova runner follows current production naming; keeping these sources explicit prevents a production rename from silently changing or breaking the frozen native comparison.

The lab exposes a native **Supernova** accessibility custom action that invokes the same store commit without a timed hold. Structural registration and deterministic store behavior do not establish VoiceOver speech/focus/activation acceptance. The lab retains ordinary clear effects: forceful impact, affected-neighbor anticipation and a comfortable reduced-motion presentation remain design work. Resolve these through a paired native play comparison before adopting or removing the lab; do not infer enjoyment from successful gesture tests. See the source-bound evidence for the exact executed checks.
