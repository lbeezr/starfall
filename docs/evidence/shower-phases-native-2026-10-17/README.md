This implements the [bounded phase design](../../design/SHOWER_PHASES.md): nine preparation showers, three pressure showers, then recovery. The pressure rule only applies when the existing natural-five-star eligibility conditions hold. It does not guarantee a tall-column landing on each burst shower.

Mechanic audit: the [same-state exposure comparison](../burst-exposure-2026-10-17/README.md) found no pressure-specific arrival changes in this seed-five fixture's first burst under canonical first clears. Use it as a cue/flow reference, not proof that the phase changes play. A five-star surge is the next offline candidate and is not installed by this export.

## Play

Run `python3 tools/mechanics/prepare-native-lab.py --burst-showers`, then build its printed `Starfall.xcodeproj` with scheme Starfall. Display name **Phase Lab**, bundle `com.starfall.burstshowerslab`, isolated defaults suite `starfall.burst-showers.lab`. No production target flag or package dependency was added. Do not import saves between candidate labs.

Launch with `--starfalls-reset --shower-phase-fixture` to begin paused after eight showers, one shower before pressure starts. Use Next shower to step through the warning and count, or Resume sky for automatic rain. Clear groups as usual. For an ordinary fresh seed-five round, use `--starfalls-reset --starfalls-seed=5`. The fixture is deterministic committed core state generated by eight normal candidate turns and canonical first clears, not a modified board or clock.

The warning says “Pressure follows this shower”; the next forecast then counts three, two and one remaining. After the last pressure shower, the next forecast says “Recovery · 9 calmer showers.” These cues describe the preview. During a falling presentation, the cue retains the committed shower's phase until that presentation finishes, matching the store's visible-forecast owner. During a clear, it continues to describe the next shower. Text is a non-color signal; announcements are posted only when the cue text changes and VoiceOver is enabled. Actual VoiceOver listening remains unverified.

No assertions or motion settings were weakened.

Before adoption, port to the settled production HUD and verify the cue remains discoverable during large-text play.
